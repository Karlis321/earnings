Q7 — Trading calendar. Don't import a market-calendar library into the cron at all. Derive trading days from the price series itself — the dates Yahoo returns a bar for a ticker are that venue's sessions. So "+1d/+3d/+1w" = step forward N bars in the security's own returned closes (and the benchmark's), intersecting the two. This is venue-agnostic (each ticker defines its own calendar), robust, and $0. pandas_market_calendars stays a local-backfill sanity check only, never in-process.

Q14 — Feedback semantics. Differentiate the two actions. "Block source" = hard exclude from all future windows. "Not relevant" on an item = (b) downweight the source's aggregate signal (feeds the source-stats re-tiering, per the reference feedback.js) + hide that one item from the current view — never hard-kill a whole source on a single bad item. Both are durable and reversible via the Feedback admin (§7.12). So: block → exclude; not-relevant → downweight + hide item.
