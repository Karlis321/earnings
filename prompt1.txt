# Stevie-style Features — Implementation Plan for Claude Code

*Adapting three YWR "Stevie" features to the BluOr Earnings & Catalyst Dashboard. Draft **v3** — grounded in the actual CI + LLM setup (the four workflow files).*

## What the real setup already gives us (so this plan is honest)

The 🔵 AI layer I previously proposed to "build" **already exists and is battle-tested**:
- **`claude-summarize.yml`** runs `anthropics/claude-code-action@v1` with `secrets.CLAUDE_CODE_OAUTH_TOKEN`, executes the `.claude/commands/earnings.md` / `sweep.md` procedures, and commits to `data/summaries/` via the git-snapshot pipe. Triggers: `/api/summarize` (repository_dispatch), schedule 04:30 UTC weekdays, manual dispatch. `--max-turns 300`.
- **`refresh-data.yml`** → `scripts/refresh-universe.mjs` computes, daily (03:00 UTC) over **~1,600 tickers** (SP500 ∪ R1000 ∪ covered): Yahoo timeseries, quoteSummary, earningsChart, **estimator (estimate revisions)**, **reactions**, market-cap — then chains to `/sweep`.
- **`extendedMetricsRegistry.ts`** = the canonical sector-KPI dictionary. **`test-standing.mjs`** = invariant CI on push/PR.
- Secrets present: `CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_API_KEY`, `FMP_API_KEY`, `TWITTERAPI_IO_KEY`, `CRON_SECRET`.

**Consequences that rewrite the plan:**
1. **Universe is ~1,600, refreshed daily.** Feature 3 "ideas" scans a real large universe now — no rescoping.
2. **Estimate revisions already exist** (the `estimator` phase). The earlier "thin estimates" worry is wrong at this scale.
3. **The AI pattern is established:** a new AI feature = a new `.claude/commands/<x>.md` procedure + a workflow that copies `claude-summarize.yml` and writes back. Reuse `refresh-universe.mjs` outputs for data.
4. **Git-safety is non-negotiable** (the Aug 18 orphan incident). Any new Claude-writing workflow MUST replicate the `claude-summarize.yml` hardening (see the ★ section).

## Stevie feature coverage — what this plan does and does NOT reproduce
This plan covers the three NEW Stevie features (adapted). It does not reproduce all of Stevie — be explicit so nobody expects parity:
- **Already have (reuse, don't rebuild):** AI Reports (= `summarize` / `earnings.md` → `data/summaries` + detail view); a factor-style estimate-revision + reaction signal over ~1,600 names (the `estimator`/`reactions` phases); the dashboard itself (replaces Stevie's Retool apps); git-snapshot DB; charting.
- **In scope here (build):** #1 Preferences (focus stocks + themes) 🟢; #1 call-snippet curation as an in-app summary field 🔵; #2 Week Ahead digest 🟢 + economic-extremity flags 🟡(new macro vendor) + narrative 🔵; #3 Ideas signal-ranking 🟢 + pitch 🔵; #4 Blue Ocean / Rule Breaker framework screens 🔵 (monthly batch).
- **Explicitly OUT of scope (flag, don't silently drop):** the conversational chat surface (this is a dashboard, not a Clawdbot); Telegram broadcast; Google Drive/Sheets/email integration; the QARV quantitative screen (feasible later, not built); portfolio-correlation & EIA tools; a literally-global 10,000-stock universe (our universe is the ~1,600 SP500∪R1000∪covered — Features 3 & 4 draw from that, not the whole world). Email delivery is OPTIONAL (free tier); the default delivery for #2/#3 is in-app.

Legend: 🟢 no LLM · 🟡 free external (macro source) · 🔵 reuses the claude-code-action + OAuth pattern.

## ★ MANDATORY for any new Claude-writing workflow (copy from claude-summarize.yml)
Do not author a fresh workflow from scratch — clone `claude-summarize.yml`'s scaffold:
- Pre-set `git config user.name/email` before Claude runs.
- Snapshot origin baseline SHA before Claude runs.
- Restrict Claude's git allowlist to `add / commit / status / log / diff / show / rev-parse / fetch` — **NO `push`, NO `init/reset/rebase/checkout --/clean/filter-*/worktree/gc/prune`, NO `--force`**.
- Post-Claude **ancestry tripwire**: `git merge-base --is-ancestor $BASELINE HEAD` must pass, and HEAD must have a parent.
- **Workflow** does the push (not Claude), with `git fetch` + `git rebase -X ours origin/main` fallback on non-fast-forward. Never force.
- `--max-turns` cap; per-ticker/per-job concurrency; timeout.

## Feature 4 — Blue Ocean / Rule Breaker framework screens (monthly AI batch)
Qualitative AI screens over the ~1,600 universe, scoring each name against a framework (Blue Ocean: value innovation / uncontested space; Rule Breakers: top-dog first-mover, sustainable advantage, management + backing, consumer appeal). Same claude-code pattern as summaries, but periodic and universe-wide.
- **4A 🔵** Encode rubrics as `.claude/commands/blue-ocean.md` + `.claude/commands/rule-breaker.md`: each framework dimension → score + one-line rationale + source, output strict JSON to `data/screens/`. Mirror the `earnings.md` discipline (validation, provenance, RESULT line). Reuse `WebSearch`/`WebFetch` (already enabled in claude-code-action) + existing summaries/fundamentals for context.
- **4B 🔵** Batch workflow `framework-screen.yml`: **monthly** cron (frameworks are near-static per stock — daily/weekly is wasteful and quota-hostile), self-chaining over the universe using the **`regenerate-summaries.yml` self-perpetuating pattern** (chain-next-before-work, concurrency group, pool-size stop) so a multi-day grind survives the 6h job cap and quota resets. **★ git-safety scaffold mandatory.**
- **4C 🟢** Screen view: new frontend view (under existing taxonomy) ranking/filtering the universe by framework score + a badge on `components/overview`; link to `app/s/[ticker]`.

**Quota reality (be honest):** ~1,600 LLM evaluations is a multi-day batch that **shares the subscription pool** with the daily `/sweep` + `regenerate-summaries`. Two options: (a) **$0** — run monthly, off-peak, via the OAuth pool with the self-chaining batch (slow but free); or (b) **isolate it** by pointing this one workflow at `ANTHROPIC_API_KEY` (you already hold the secret; metered Haiku is cheap) so the bulk screen never starves the daily summarize quota — small $ cost, breaks strict $0. Recommend (a) first; switch to (b) only if the screen contends with daily jobs.
